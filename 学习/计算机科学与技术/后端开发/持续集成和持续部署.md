# DevOps
一组将软件开发（Dev）和 IT 运维（Ops）相结合的实践和理念。旨在通过促进开发团队和运维团队之间的协作、自动化流程以及持续集成和持续交付（CI/CD），提高软件交付的速度、质量和可靠性，以实现更高效的软件开发和运维流程。
## 持续集成（Continuous Integration，CI）
持续集成一种软件开发实践。指开发人员频繁地将代码集成到共享代码库中，每次集成都通过自动化构建来验证，从而尽早地发现错误。在多人协作开发过程中，能最大限度确保每次代码合并都是平稳且无误的。而且持续集成减少了手动构建和测试的时间，开发人员可以把更多精力放在开发新功能上。
## 持续部署（Continuous Deployment，CD）
持续部署是指将经过测试的代码自动部署到生产环境中。通过持续部署，开发团队可以频繁且可靠地向生产环境发布代码，减少了手动部署的步骤，降低了人为错误的风险。用户也可以及时得到反馈。而且持续部署使得开发团队可以频繁发布新功能和修复 bug，提高产品的竞争力。
# CI/CD 工具
## Jenkins
###### Docker 安装 Jenkins
**拉取 Jenkins 镜像**：`docker pull jenkins/jenkins`
**创建容器并启动 Jenkins**：
```bash
docker run -d -p 8099:8080 -p 50099:50000 -v /home/jenkins:/var/jenkins_home --name jenkins jenkinsci/blueocean
```
**访问 `Jenkins`**：浏览器 `http` 访问 `8099` 端口。
**获取访问密码**：密码存放在：`/home/jenkins/secrets/initialAdminPassword`。
## GitHub Actions
### 简介
- Workflow：工作流，指一个自动化的过程。在 GitHub Actions，工作流信息配置在 `.github/workflows` 目录下的 `.yml` 文件。
- Event：事件。是触发工作流的条件。比如 git push、pull request。
- Jobs：任务，一个工作流可以有多个任务。
- Steps：步骤。指每个任务里具体做的事。
### 使用
GitHub Actions 会自动寻找项目根目录下 `.github/workflows/` 目录中的各种 `.yml` 文件。你可以在根目录创建文件夹`.github/workflows`，并且在该文件夹下新建一个`yml`文件（如命名为 `maven-build.yml`）。
```yaml
# 工作流的名字
name: Java CI with Maven

# 指定触发时机
on:
  push:
    branches: [ "main" ]  # 当代码 push 到 main 分支时触发
  pull_request:
    branches: [ "main" ]  # 当有 PR 合并到 main 分支时触发

# 执行的任务
jobs:
  build:
    # 指定运行环境（这里使用最新的 Ubuntu 虚拟机）
    runs-on: ubuntu-latest
    
    # 执行步骤
    steps:
    # 第一步：下载仓库代码到虚拟机上
    - name: Checkout code
      uses: actions/checkout@v4
    # 第二步：安装并配置 Java 环境
    - name: Set up JDK 17
      uses: actions/setup-java@v4
      with:
        java-version: '17'      # 根据你项目的 JDK 版本修改 (8, 11, 17, 21等)
        distribution: 'temurin' # 常用发行版
        cache: maven            # 开启缓存，下次打包会快很多

    # 第三步：执行 Maven 打包命令
    - name: Build with Maven
      run: mvn -B package --file pom.xml

    # 第四步（可选）：将打包好的 jar 包上传到 GitHub 页面，方便你下载
    - name: Upload Artifact
      uses: actions/upload-artifact@v4
      with:
        name: springboot-app-jar  # 下载时的文件名
        path: target/*.jar        # 上传 target 目录下生成的 jar 包
```
uses: actions/setup-java@v4：别人写好的现成插件。checkout 负责把你的代码拉取到虚拟机里。
cache: maven：第一次下载依赖非常慢。开启缓存后，GitHub 会把这些依赖存起来，下次只要 pom.xml 没变，它就不会重新下载。
