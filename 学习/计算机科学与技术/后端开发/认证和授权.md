# 认证

## 登录认证
### Cookie
后端服务器在返回响应请求时，在响应头携带 cookie 字段，其中存放一组键值对。可以携带多组 cookie。
```json
set-cookie:key1=value1
set-cookie:key2=value2
set-cookie:key3=value3
...
```
浏览器接收到具有 cookie 的响应后，会将 cookie 保存在浏览器中，并在以后向同一个域名发起后续请求时，在请求的请求头中携带此 cookie 一并发送给后端服务器。
### Session
session 是基于 cookie 实现的，这种机制能够一定程度上解决使用原 cookie 机制时存在的信息泄露问题。
由后端服务器管理一系列状态字段，这一系列状态字段统称为：session 上下文。后端通过 cookie 返回给前端一个唯一标识 session 上下文的 id，称为 session id。
浏览器接收并保存 session id，并在后续请求时携带此 id 一并发送给后端，后端根据这个唯一 id，找到 id 对应的 session 上下文，判断请求是否有效。
### Token 和 JWT
后端将状态字段相关信息构造在一串称为 token 的加密字符串中，携带至请求头 `Authorization: token`，将此 token 发送给前端。
前端接收并保存 token，并在后续请求时携带此 token 一并发送给后端。
后端后续请求接收到 token 后，解密 token 内容，得到原始状态字段信息，判断请求是否有效。
#### JWT
JWT（JSON Web Token）是一种用于在网络应用中传输信息的开放标准（RFC 7519），通常被用于对用户进行身份验证和授权。是 token 的标准实现。
特点是无状态、服务器无需存储 token、验证只靠签名和过期时间。
若想实现**续签**和**主动过期**，须引入状态。
#### JWT 的组成
JWT 由三部分组成，每个部分之间使用点符号（.）进行分隔。
```C++
Header.Payload.Signature
```
- Header：包含 token 的元数据和使用的签名加密算法信息。Header 是一个 Base64Url 编码通常是 JSON 对象后的字符串。JSON 对象负责存储 token 的元数据和使用的签名加密算法信息。Base64Url 负责对这段 JSON 进行编码。
- Payload：包含 token 要传输的自定义数据，如用户的身份信息。Header 是一个 Base64Url 编码通常是 JSON 对象后的字符串。
- Signature：使用 Header 指定的加密算法对 Header 和 Payload 进行签名后的签名字符串。签名用于确认令牌在传输过程中有没有被篡改。JWT Signature 使用数字签名算法生成摘要。
#### JWE
加密的 JWT，称为 JWE（JSON Web Encryption）。
# 授权
## 权限
- 访问权限：是否可以访问系统中的各种数据和信息。
- 执行权限：是否可以执行系统中的各种操作和功能。
- 控制权限：是否可以对系统进行管理和控制。
- 共享权限：是否可以与其他用户共享某些信息。
## 权限管理
管理系统中用户的**权限**。使只有经过**授权**的用户才能行使。
目的是确保信息和资源的安全性、完整性和保密性。防止未经授权的活动或滥用。

### 依赖和配置
#### Maven 依赖
```xml
<!-- SpringBoot Security -->  
<dependency>

```
#### 配置
`SpringSecurityConfig` 本质上是把 `Spring Security` 的各种能力（认证、授权、会话策略、CSRF、防护、过滤器链、异常处理、OAuth/JWT 等）以 `Bean` 的形式声明出来，交给 Spring 管理。Spring Security 6+ 推荐的做法是通过 `SecurityFilterChain`、`UserDetailsService`、`PasswordEncoder`、以及可选的 `AuthenticationManager` 来配置。
不推荐早期的 `WebSecurityConfigurerAdapter` 继承方式。
##### SecurityFilterChain
核心配置 `Bean`。用于拦截请求并应用安全规则的过滤器链。
###### HttpSecurity
用于构建过滤器链和配置请求级别的安全策略（授权规则、登录、登出、CSRF、CORS 等）。
- `authorizeHttpRequests`
	- 使用 `requestMatchers(...)` 指定需要鉴权的请求路径；使用 `anyRequest()`表示所有请求路径。
		- `.permitAll()`：请求无需认证即可访问。
		- `.authenticated()`：请求需要认证才能访问。
- `csrf`
	- 默认开启。Spring Security 默认拒绝所有 POST 请求。若是前后端分离项目，需要关闭 `csrf`：`.csrf().disable()`
- `cors`
	- 跨域配置。
- `add.addFilterBefore()`添加自定义过滤器。
	- `UsernamePasswordAuthenticationFilter` 是 Spring Security 默认处理表单登录的过滤器，用于从登录表单读取用户名和密码，然后生成认证对象。
	- 自定义过滤器类需要继承`OncePerRequestFilter`抽象类并实现`doFilterInternal`方法。
		- `OncePerRequestFilter` 是 Spring 提供的一个 过滤器基类（Filter），用来处理 HTTP 请求。每个请求只会调用一次，不会重复执行。
		- `doFilterInternal`：定义过滤器真正要做的事情。
	- 添加自定义 JWT 过滤器：`.and().addFilterBefore(new JwtAuthenticationFilter(), UsernamePasswordAuthenticationFilter.class);`
###### 自定义过滤器
自定义过滤器需要继承 `OncePerRequestFilter`抽象类并实现 `doFilterInternal`方法。在 `doFilterInternal`方法中，若验证通过，配置 Spring Security 认证上下文以通过认证。
```Java
UsernamePasswordAuthenticationToken authentication = new UsernamePasswordAuthenticationToken(jwtInfo.getUserId(), null, null);
SecurityContextHolder.getContext().setAuthentication(authentication);
filterChain.doFilter(request, response);
```
- `UsernamePasswordAuthenticationToken`：Spring Security 用来表示 当前认证用户身份的对象。
	- Object Principal：主体。标识登录用户。
	- Object Credentials：认证凭证。可存储 token。
	- Authorities：权限列表。用户的角色或权限，若基于角色控制访问，传递 `List<GrantedAuthority>`。
- `SecurityContextHolder`：Spring Security 全局的上下文容器，每个请求都有一个独立的上下文。调用 `setAuthentication(authentication)` 后，Spring Security 会把这个用户当作已认证的用户。后续请求中，可通过`SecurityContextHolder.getContext().getAuthentication()` 获取当前用户信息。
