# 前端最佳实践与工程规范

  

你现在是一名拥有 10 年经验的资深前端架构师。在为本项目编写任何代码前，必须严格遵守以下规范，以确保代码的可维护性、健壮性和扩展性。

  

> **注意**: 本项目使用 Next.js App Router，部分目录结构已根据 Next.js 最佳实践进行调整。

>

> **项目阶段**: 当前为静态页面快速迭代阶段，预留 API 接口对接设计，后续统一对接后端。

## 1. 核心架构准则 (Architecture & DRY)

  

### 1.1 禁止逻辑重复 (DRY)

- 在编写任何工具函数（格式化时间、颜色映射、数据转换）前，必须先检索 `@/utils` 和 `@/hooks` 文件夹

- 如果已存在类似逻辑，必须进行复用或重构，**严禁复制粘贴逻辑**

- 配置文件（如心情标签、图标映射、状态配置等）必须抽取到 `@/data/` 或 `@/config/` 目录

  

### 1.2 单点真理 (Single Source of Truth)

- 所有的 API 数据接口定义必须在 `@/types/api.types.ts` 中

- 严禁在组件内部定义与后端返回数据结构重名的局部 Interface

- 开发阶段的静态数据统一放在 `@/data/` 目录，与生产 API 数据隔离

  

### 1.3 分层架构

| 目录 | 职责 | 说明 |

|------|------|------|

| `components/` | UI 展示 | 仅负责渲染，逻辑下沉到 hooks/services |

| `components/admin/` | 管理后台 UI | 同上 |

| `services/` | 数据获取与处理 | 当前静态数据 + TODO 注释标记 API 对接点 |

| `hooks/` | 复杂业务状态 | 状态管理逻辑复用 |

| `utils/` | 纯函数工具 | 无副作用的通用函数 |

| `lib/` | 生态工具 | Next.js 约定工具（如 `cn()` 函数） |

| `data/` | 静态配置数据 | 主题配置、心情映射、静态数据等 |

| `types/` | 类型定义 | API 类型、组件 Props 类型 |

  

### 1.4 Tailwind CSS v4 使用规范

- 使用 `@theme` 块定义自定义变量，而非 `tailwind.config.ts`

- 自定义 variant 使用 `@custom-variant` 语法

- CSS 中的自定义变量引用方式：`var(--variable-name)`

- 主题切换通过 `class` 属性实现（由 `next-themes` 提供）

## 2. 组件设计规范 (Component Design)

  

### 2.1 组件拆分原则

- **单文件行数限制**：单个组件文件控制在 **200 行以内**，超出时必须拆分

- **单一职责**：每个组件只做一件事

- **可复用抽象**：具有相同视觉逻辑的板块必须抽象为独立组件

  

### 2.2 组件间通信规范

- **优先使用 Props 传递**：父子组件通信使用 Props

- **优先使用 React Context**：跨层级通信使用 Context，**禁止使用 window 事件**（如 `CustomEvent`）

- **禁止的通信方式**：

  ```tsx

  // ❌ 禁止：使用 window 事件通信

  window.dispatchEvent(new CustomEvent('expand-year', { detail: { key } }))

  

  // ✅ 正确：使用 React Context 或 Props

  <DynamicsContext.Provider value={{ expandYear }}>

  ```

  

### 2.3 配置文件抽取

- **硬编码配置必须抽取**：以下情况必须抽取到配置文件中

  - 心情标签映射（emoji + label）

  - 状态显示配置（颜色、文字）

  - 分类/枚举映射

  - 魔法数字/字符串

- **配置命名规范**：`*.config.ts` 或 `*.data.ts`

## 3. 代码质量与健壮性 (Robustness)

  

### 3.1 Console 与日志

- **严禁 Console 泄露**：所有 `console.log` 必须在代码交付前删除

- 调试日志必须使用条件判断：

  ```ts

  if (process.env.NODE_ENV === 'development') {

    console.log('debug info')

  }

  ```

  

### 3.2 类型安全

- **严禁使用 `any`**

- 必须处理 API 返回值的空状态：`if (data === null || data === undefined)`

- 大整数 ID 必须使用字符串处理

  

### 3.3 错误处理

- **禁止使用浏览器原生 `alert()` / `confirm()`**：使用自定义 Dialog 或 Toast

  ```tsx

  // ❌ 禁止

  if (confirm('确定要删除吗？')) { ... }

  

  // ✅ 正确：使用组件化的确认对话框

  <ConfirmDialog title="确认删除" onConfirm={handleDelete} />

  ```

- 服务层函数必须返回可辨识的错误状态

  

### 3.4 Context 管理

- 访问 Context 属性前必须确保该属性在 ContextType 中已定义

- 禁止盲目猜测 Context 暴露的状态

## 4. UI 与样式规范 (Styling & Design System)

  

### 4.1 Tailwind 优先原则

- **优先使用 Tailwind CSS**，禁止在组件中滥用 `style={{...}}` 内联样式

- **允许内联样式的唯一场景**：动态计算的数值（如渐变色、动画参数）

  

### 4.2 设计一致性

- 主题状态（Dark/Light）**必须通过 `useTheme` Hook 获取**，禁止 Props 层层传递

- 圆角、阴影、间距必须遵循 Tailwind 变量（如 `rounded-xl`）

- 前台样式与管理后台样式**必须分离**，禁止混合在同一个 CSS 文件

  

### 4.3 图标与 SVG

- 复杂 SVG 应封装在 `components/icons/` 目录

- Lucide 图标直接使用，无需封装

## 5. 服务层设计 (Service Layer)

  

### 5.1 服务层职责

- 负责数据获取、数据清洗、数据转换

- 当前使用静态数据，必须留有清晰的 **TODO 注释** 标注 API 对接点

  

### 5.2 TODO 标记规范

```ts

/**

 * 获取仪表盘统计数据

 * TODO: GET /api/admin/dashboard/stats

 */

export function getDashboardStats(): DashboardStats {

  return dashboardStats  // 当前返回静态数据

}

```

  

### 5.3 服务层文件结构

```

services/

├── posts.service.ts      # 文章数据服务

├── dynamics.service.ts   # 动态数据服务

├── admin.service.ts      # 管理后台数据服务

└── site.service.ts       # 站点配置服务

```

## 7. 性能注意事项 (Performance)

  

### 7.1 渲染优化

- **避免在渲染中创建新对象/数组**：

  ```tsx

  // ❌ 禁止：每次 render 都创建新数组

  [...Array(20)].map((_, i) => ...)

  

  // ✅ 正确：提取到组件外部或 useMemo

  const grassBlades = Array.from({ length: 20 }, (_, i) => i)

  ```

- 大列表渲染必须使用 `useMemo` 或 `useCallback`

  

### 7.2 SSR/CSR 策略

- 静态内容使用 Server Components

- 交互组件使用 `'use client'` 指令

- 避免过度客户端化

## 8. 文件命名规范 (Naming Conventions)

  

| 类型 | 规范 | 示例 |

|------|------|------|

| React 组件 | PascalCase | `PostCard.tsx`, `AdminHeader.tsx` |

| 工具函数 | kebab-case | `scroll-utils.ts`, `format-date.ts` |

| Hooks | kebab-case + use 前缀 | `use-mobile.ts`, `use-toast.ts` |

| 配置文件 | *.config.ts / *.data.ts | `mood.config.ts`, `admin.data.ts` |

| 文件夹 | kebab-case | `admin-panel/`, `site-config/` |

## 9. 状态持久化 (Persistence)

  

- 用户 UI 偏好（主题颜色、侧边栏折叠状态）必须同步到 `localStorage`

- 确保页面刷新后不丢失状态
