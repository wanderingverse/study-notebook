# 消息队列
## 消息队列概述
消息队列（Message Queue）是一种用于存取消息的队列。
## 消息队列的应用场景
### 异步处理
如在电商类网站中，新用户注册时需要将用户的信息保存到数据库中，同时还需要额外发送注册的邮件通知以及短信注册码给用户。但因为发送邮件、发送注册短信需要连接外部的服务器，需要额外等待一段时间，此时可以使用消息队列进行异步处理，实现快速响应。
### 系统解耦
如在电商类网站的微服务系统中，订单系统和库存系统是两个独立的微服务，当用户下订单之后，订单系统处理订单，需要与库存系统交互。传统微服务之间通过 API 进行调用，会产生时间耦合（如两方必须同时在线）和接口耦合（如接口参数、格式、协议变更后互相影响）。但这种方式会让两个系统间产生耦合，比如 API 发生变化，请求方和调用方都需要修改。通过消息队列，订单系统将消息发送到消息队列，库存系统从消息队列消费消息，两系统一个生产消息、一个消费消息，各自只对消息负责，解除了两个系统之间存在的耦合：时间解耦（生产者和消费者不必同时在线）和通信方式解耦（不需要直接 RPC 调用），而原有两服务之间的接口耦合则转换为各自对消息的耦合。
### 削峰填谷
在高并发场景下，大量流量和请求瞬时涌入服务器，很容易超过服务器能处理的上限，最终导致服务不可用。使用消息队列作为缓冲区后，所有请求积压在消息队列，排队等待业务处理服务器逐一处理，此时业务系统按自身能力进行消费，保证了服务稳定，避免雪崩、宕机等问题。而在低流量时段，积压在消息队列中的任务可被继续处理，充分利用了资源，稳定保证服务器的处理能力。
### 日志处理
大型网站在分析用户行为时，比如要根据用户的访问行为来发现用户的喜好以及活跃情况，需要收集大量的用户访问信息存储和分析。如果所有分析处理程序都直接从应用服务器获取日志，会造成耦合高、性能瓶颈、扩展困难等问题。引入消息队列，可作为临时存储或者通信管道，用户产生的日志信息由应用服务器发送到消息队列，然后由（众多）实时处理程序从消息队列消费消息并处理。降低了应用服务器的压力，提高了日志分析和处理效率。

## 消息队列中间件
消息队列中间件指基于消息队列的、用于存取消息的组件。常见的消息队列中间件有：Kafka、RabbitMQ、RocketMQ 等。
