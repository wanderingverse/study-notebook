##### 限制
- 一个表中最多可以包含 1017 列（≈ 2<sup>10</sup> 列），包含虚拟生成的列。
- 一个表中最多可以包含 64 个（2<sup>7</sup> 个）二级索引（非主键索引）。
	- 一个表中最多可以有 64+1=65 个索引，包含 1 个主键索引和最多 64 个二级索引。
- 多列索引（复合索引）最多允许 16 列（2<sup>4</sup> 列）。 超过限制将返回错误。
### 命令和语句
#### 命令
- 连接 MySQL：`mysql -h <ip> -u <username> -p<password>`
	- ip：MySQL 数据库连接地址，缺省时默认连接 localhost。
	- username：MySQL 用户名。
	- password：用户名密码。
		- `-p` 和密码之间不能有空格。MySQL 官方安全规范不允许直接在 `-p` 后面用空格跟密码（可以用无空格写法，但不推荐，因为密码会暴露在命令历史里）。

#### DML
DML（Data Manipulation Language），数据操作语言。用于对数据库中已经存在的数据进行操作，如插入、更新、删除、查询数据。
#### DDL
DDL（Data Definition Language），数据定义语言。用于定义和管理数据库对象，如创建、修改、删除数据库（表、索引、视图、约束）等。

- 左连接：从左表中返回所有记录，并同时返回右表中与左表匹配的记录。如果右表中没有匹配的记录，则结果中右表的列将显示为 NULL。
```mysql
SELECT 列名 FROM 左表 LEFT JOIN 右表 ON 左表.关联列 = 右表.关联列;
```
- 内连接：只返回两个表中满足连接条件（`ON` 条件）且匹配成功的记录。如果某一行在左表或右表没有匹配项，则不会出现在结果中。其中，inner 关键字可省略。
```mysql
SELECT 列名 FROM 左表 INNER JOIN 右表 ON 左表.关联列 = 右表.关联列;
```
- 分组聚合：对表中的数据根据一个或多个字段进行分组，并对每组应用聚合函数，得到每组的汇总结果。
	- 聚合函数：
		- `COUNT(column)`：统计某列非空值的数量。
		- `COUNT(*)`：统计行数（不排除空值）。
		- `SUM(column)`：求某列的数值总和。
		- `MAX(column)`：求某列的最大值。
		- `MIN(column)`：求某列的最小值。
		- `AVG(column)`：求某列的平均值。
```mysql
SELECT 分组列1, 分组列2, 聚合函数(列名) AS 聚合结果别名  
FROM 表名  
WHERE 条件  
GROUP BY 分组列1, 分组列2  
HAVING 聚合函数(列名) 条件;
```
- 排序：对表中的数据根据指定的排序条件和排序方式进行排序，返回排序后的结果。当排序方式缺省时，使用默认排序方式：升序排序。
	- 排序方式：
		- desc：降序排序。
		- asc：默认排序方式，升序排序。
```mysql
SELECT * FROM 表名 WHERE 条件 order by 列名 排序方式;
```
- 删除：用于从表中删除一行或多行数据，根据 `WHERE` 条件指定需要删除的记录。如果缺省 `WHERE` 条件，则会删除表中的所有数据。
```mysql
DELETE 表名 FROM 表名 WHERE 条件;
```

### 执行计划
执行计划（**Execution Plan**）供开发者观察数据库实际如何执行一条指定的 SQL 。
```mysql
explain SQL语句;

# MySQL 8.0+
EXPLAIN ANALYZE SQL语句;
```
- `id`：执行计划中每个查询块的编号，表示执行步骤。`id` 越大，优先级越高，查询越先执行。
- `select_type`：查询类型
	- SIMPLE：简单 SELECT，没有子查询或 UNION。
- `table`：当前这行查询对应的表名。
- `type`：访问类型
	- ALL：全表扫描
	- index：全索引扫描：全表扫描索引，不扫描数据文件。
	- range：索引范围扫描。
	- ref：非唯一索引匹配。
	- eq_ref：唯一索引匹配，且每次返回一行。
	- const：一次访问，表示常量值。
	- system：表只有一行。
- `possible_keys`：优化器（Optimizer）认为可以使用的索引，即候选索引。
- `key`：实际使用的索引。
- `key_len`：使用索引的长度（字节），反映了索引的使用情况。
- `ref`：用哪个列或常量与索引进行比较。
- `rows`：粗略估算这一次查询要扫描的数据行数。
	- 结合 `filtered` 查看实际处理的数据行：`实际输出行数 = rows × (filtered / 100)`
- `filtered`：过滤后的行占比。
	- `filtered` 越低，说明过滤条件越严格：要扫描的数据多但真正用到的不多。反映这可能是一个优化点。
	- `filtered` 越高，说明大部分行都会被保留，过滤开销小，或者过滤条件宽松。
- `Extra`：额外信息
	- `Using where`：使用了 `WHERE` 条件过滤。
	- `Using join buffer`：使用了连接缓冲区（一般是因为没有索引支持 `JOIN` 条件）。
### 索引
#### 索引设计原则
- **数据量少的表或更新频繁的表不适合加索引**：当表的数据量很小（如几百条以内），数据库在执行 SQL 查询时，全表扫描比使用索引更快。而且索引是一个额外的结构，会占用内存或磁盘空间。对小表或频繁更新的表来说，维护这些索引（如插入/删除/更新时自动更新索引）会带来额外负担，却不能带来明显的性能提升。在高并发写入的场景中，索引越多，写操作的性能越差，因为每次写入都要先锁定和更新多个索引。

#### MySQL 异步复制
在传统主从架构设计中，主库实例提交事务与发送二进制日志是异步的，从库是否成功接收到二进制日志不会影响到主库事务提交，因此可能会出现一种情况：主库发生宕机，主库已提交事务的二进制日志并没有被任何从库成功接收的情况，进而数据丢失。
##### 配置 MySQL 异步复制
1. 主库开启 `binlog` 日志用于数据同步：修改 `my.cnf` 或 `my.ini` 文件。在配置文件中的`[mysqld]`下增配如下内容：
```C++
[mysqld]
# 设置 server-id（标识主库的唯一 id），必须是一个正整数，且在整个复制集群中必须唯一。
server-id = 1
# 启用 binlog日志并指定存储路径
log-bin = ./mysql-bin
# 开启 GTID
gtid_mode = ON
enforce_gtid_consistency = ON
# binlog 刷写策略
sync-binlog = 1
# binlog 刷写格式，row 为最安全严谨的格式
binlog-format = row
# binlog 文件存储大小，存满 1G 后会自动置换下一个文件
max_binlog_size = 1G
# binlog 自动清理时常，单位天，设置为 30 会自动清理 30 天前的 binlog 日志
expire_logs_days = 30
```
2. 创建用于同步的用户：`create user 'replication'@'%' identified by '123456';`
3. 授权读取二进制日志（binlog）事件的权限：
```mysql
grant replication slave on *.* to 'replication'@'%';
```
4. 刷新权限，使权限配置生效：`flush privileges;`
5. 重启主库 MySQL，使配置生效。
6. 查看 GTID 启用状态
	- `SHOW VARIABLES LIKE 'gtid_mode';`
	- `SHOW VARIABLES LIKE 'enforce_gtid_consistency';`
7. 查看 binlog 信息：`show master status`，观察配置完成情况，并获取：
	- `File`：当前主库正在写入的二进制日志文件名
	- `Position`：当前二进制日志文件中的写入位置
	- `Executed_Gtid_Set`：主库当前 GTID。
8. 修改从库 MySQL 配置文件
	- 中继日志`relay_log`：中继日志是 MySQL 从库（Slave）上负责存储从主库（Master）接收到的二进制日志事件（binlog events）的文件，作用是临时存储从主库接收到的变更事件，然后由SQL线程（SQL Thread）读取并应用到从库。如果不设置 relay_log 参数，从库默认会使用`host_name-relay-bin`作为文件名前缀。
	```C++
	[mysqld]
	# 设置 server-id（标识数据库实例的唯一 id），必须是一个正整数，且在整个复制集群中必须唯一。
	server-id = 2
	# 设置中继日志保存路径
	relay_log = ./relay-log-bin
	# 开启 GTID
	gtid_mode = ON
	enforce_gtid_consistency = ON
	# 限制从库普通用户只读
	read_only = 1
	# 限制从库超级用户只读
	super_read_only = 1
	```
9. 重启从库 MySQL，使配置生效。
10. 建立从库（slave）与主库（master）数据的复制关系，两种方式二选一。
	- 【不推荐】binlog + 偏移量式
		```mysql
		# binlog + 偏移量式
		CHANGE MASTER TO
			MASTER_HOST ='192.168.102.33',
		    MASTER_USER ='replication',
		    MASTER_PASSWORD ='123456',
		    MASTER_PORT =3306,
		    MASTER_LOG_FILE ='mysql-bin.000001',
		    MASTER_LOG_POS =154,
		    MASTER_CONNECT_RETRY =10;
		```
	- 【推荐】GTID 式
		```mysql
		# GTID 式
		CHANGE MASTER TO
			MASTER_HOST ='192.168.102.33',
		    MASTER_USER ='replication',
		    MASTER_PASSWORD ='123456',
		    MASTER_PORT =3306,
		    MASTER_AUTO_POSITION=1,
		    MASTER_CONNECT_RETRY =10;
		```
11. 开启异步复制：在从库执行`START SLAVE;`
12. 检查复制状态：在从库执行`SHOW SLAVE STATUS`
	- `Slave_IO_Running`: Yes：从库的 I/O 线程是否在正常连接主库并读取 binlog。
	- `Slave_SQL_Running`: Yes：从库的 SQL 线程是否在正常执行 I/O 线程获取到的 binlog。
13. 停止异步复制：在从库执行`stop slave;`
14. 重置主从复制
	1. 在从库执行`reset slave all`
	2. 在主库执行`reset master`
